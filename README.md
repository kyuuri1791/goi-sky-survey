# 日本語語彙スカイサーベイ(β版)

日本語の約 39 万語を使われ方の近さで平面に並べたWebアプリです。暗い背景に光る点として眺め、拡大すると、あまり使われない語が少しずつ現れます。

## 機能

- 見る: ドラッグで移動、ホイールかピンチで拡大。点の明るさは語がよく使われる度合い、色は品詞
- 探す: 語で検索するとその位置へ飛び、使われ方の近い語 8 つと線でつながる。点を押しても同じ
  - 語彙にない複合語は、語彙にある語に分けて意味を合わせて探す(家系ラーメン → 家系 ＋ ラーメン → 醤油ラーメン、豚骨ラーメン…)
- 共有: 選んでいる語は URL(`/?w=語`)に入り、パネルの「Xで共有」から X の投稿画面を開ける

## 仕組み

### 語のベクトルと近さ

- 単語は [chiVe](https://github.com/WorksApplications/chiVe) のv1.3 mc90(出現回数90回以上の約41万語、300次元ベクトル)を利用している
- 近さはコサイン類似度により算出

### 平面への配置(`pipeline/layout.py`)

コサイン類似度による距離の入った300次元のベクトル空間を2次元に写すにあたって、遠い語どうしの距離ではなく「近所づきあい」が保たれるようにしている
  - 具体的には[UMAP](https://github.com/lmcinnes/umap) で並べている
  - 大体はいい感じに並んでいますが、300次元を無理やり2次元に並べているのでちょいちょい思いっきりズレています...

### 使われ方の近い語の検索

v1.3 mc90 の各単語に対する近傍の語はデータを作る段階で前計算している(`pipeline/neighbors.py`)ので入力された語が存在する場合、検索時には表を引くだけとなります。入力が語彙にある単語を組み合わせた複合語の場合、このベクトルは(ほぼ)R^300 の任意の元とみなせて前計算しておけないので、検索のたびに全部の語と比べています。各語のベクトルは 1 バイトに丸めて SQLite のファイル(`data/vectors-*.db`)に入れておき、サーバーではパッチを当てた [sqlite-vec](https://github.com/asg017/sqlite-vec) で引いています。(パッチを当てているのは内積計算でSIMDを効かせて高速化するため)

| 方法 | 本物の上位10語を当てた割合 | 1回の検索 |
|---|---|---|
| 総当り(丸めないベクトル、配布版sqlite-vec) | 100% | 約 220ms |
| 総当り(1バイトに丸めたベクトル、配布版sqlite-vec) | 99% | 約 210ms |
| **総当り(1バイトに丸めたベクトル、パッチ版sqlite-vec)** | **99%** | **約 60ms** |

(よく使われる3万語から2語ずつ選んで足した200組を問い合わせにした測定、1回の検索は39万語全部と比べる時間をローカル(Ryzen 5 7540U)で測ったもの)

## 開発
Linux x64で動かす想定です。
```bash
npm install
npm run dev
```

### データの作り直し

Python(`pipeline/`)で作って`data/`に SQLite のファイルとして出力します。Docker上で動かしています。(docker, docker-composeがインストールされていることが前提となります)

```bash
npm run data:all     # data/ を作り直す
npm run data:bench   # 複合語の検索の精度を測る
```

### NGリスト

NGリストで不適切な言葉を除外しています。リストの中身は公開しないため、AES-256-GCM で暗号化した `pipeline/ng.enc` だけをリポジトリに入れています。

鍵は git 管理対象外で、`pipeline/.env` の `NG_KEY` から読みます(`pipeline/ngcrypt.py`)。

```bash
npm run ng:edit      # 復号してエディタで開き、保存すると暗号化し直す(その後 pipeline/ng.enc をコミットする)
```
### パッチの当て直し

何らかの理由でパッチ(`vendor/sqlite-vec/int8-cosine.patch`)を変えた場合:
```bash
sh vendor/sqlite-vec/build.sh
```
